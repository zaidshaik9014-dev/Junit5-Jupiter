# Maven + JUnit 5 (Jupiter) Learning Repository

A practical Java learning repository covering **Apache Maven** and **JUnit 5 / JUnit Jupiter** through multiple small Maven projects and hands-on examples.

The goal is to understand how Maven builds Java projects and how JUnit tests Java code, including lifecycle management, assertions, practical application testing, and database testing with H2/JDBC.

## Repository Structure

```text
maven-learning/
├── 1/
├── 2/
│   └── ECommerceCart/
├── Junit-06/
├── Junit-07/
├── Junit-08/
├── calculator/
└── README.md
```

Each folder is a separate Maven project with its own `pom.xml`.

`target/` directories are generated by Maven and normally should not be committed to Git.

# Maven

## Creating a Maven Project

The modern Maven Quickstart archetype used for these projects:

```bash
mvn archetype:generate -DgroupId=com.zaidi -DartifactId=my-app -DarchetypeArtifactId=maven-archetype-quickstart -DarchetypeVersion=1.5 -DinteractiveMode=false
```

### Command breakdown

```text
mvn
```
Runs Maven.

```text
archetype:generate
```
Runs the Maven Archetype plugin's `generate` goal.

```text
-DgroupId=com.zaidi
```
Sets the project group ID.

```text
-DartifactId=my-app
```
Sets the project/artifact name.

```text
-DarchetypeArtifactId=maven-archetype-quickstart
```
Uses the Maven Quickstart template.

```text
-DarchetypeVersion=1.5
```
Uses Quickstart archetype version 1.5.

```text
-DinteractiveMode=false
```
Creates the project without interactive prompts.

## POM

`pom.xml` is the **Project Object Model** and contains project configuration such as:

- groupId
- artifactId
- version
- Java version
- dependencies
- plugins
- build configuration

A project's coordinates are commonly represented as:

```text
groupId : artifactId : version
```

## Dependencies

A dependency adds an external library to the project.

Example:

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter-api</artifactId>
    <scope>test</scope>
</dependency>
```

### `dependencies` vs `dependencyManagement`

`dependencies` actually adds a dependency to the project.

`dependencyManagement` manages versions/configuration for dependencies declared elsewhere. By itself, it does not add the dependency to the project.

## Maven Lifecycle

Important lifecycle phases:

```text
validate
   ↓
compile
   ↓
test
   ↓
package
   ↓
verify
   ↓
install
   ↓
deploy
```

Useful commands:

```bash
mvn clean
mvn compile
mvn test
mvn clean test
mvn package
mvn install
```

`mvn dependency:tree` can be used to inspect the dependency tree.

## Plugins, Goals and Phases

A useful mental model:

```text
Maven Phase
    ↓
Plugin
    ↓
Goal
```

Maven Surefire is used during the test lifecycle to execute tests.

# JUnit 5 / Jupiter

JUnit 5's programming model is called **JUnit Jupiter**.

The repository covers core testing concepts and practical examples.

## Basic Test

```java
@Test
void testSomething() {

    int result = 10 + 20;

    assertEquals(30, result);
}
```

A useful structure for tests is:

```text
ARRANGE
Prepare required data
        ↓
ACT
Call the method/code being tested
        ↓
ASSERT
Verify the result
```

# Assertions

## `assertEquals`

Checks that expected and actual values are equal.

```java
assertEquals(30, result);
```

Conceptually:

```text
Expected = 30
Actual   = result

Expected == Actual
       ↓
     PASS
```

## `assertNotEquals`

Checks that two values are different.

```java
assertNotEquals(50, result);
```

## `assertTrue`

The condition must be `true`.

```java
assertTrue(result > 0);
```

## `assertFalse`

The condition must be `false`.

```java
assertFalse(connection.isClosed());
```

For example:

```text
connection.isClosed()
       ↓
     false
       ↓
assertFalse(false)
       ↓
     PASS
```

## `assertNull`

Checks that a value is `null`.

```java
assertNull(value);
```

## `assertNotNull`

Checks that a value is not `null`.

```java
assertNotNull(connection);
```

# JUnit Lifecycle

## `@BeforeEach`

Runs before every test.

```java
@BeforeEach
void setUp() {
    cart = new ShoppingCart();
}
```

Useful when every test needs fresh state.

```text
@BeforeEach → Test 1
@BeforeEach → Test 2
@BeforeEach → Test 3
```

## `@AfterEach`

Runs after every test.

```java
@AfterEach
void cleanUp() {
    // test-specific cleanup
}
```

## `@BeforeAll`

Runs once before all tests in a test class.

```java
@BeforeAll
static void setUpDatabase() {
    // shared setup
}
```

Useful for resources such as a database connection that should be created once.

## `@AfterAll`

Runs once after all tests in a test class.

```java
@AfterAll
static void closeDatabase() {
    // shared cleanup
}
```

Useful for closing resources created in `@BeforeAll`.

---

# `@TestInstance(PER_CLASS)`

JUnit normally uses a separate test class instance for each test method.

`PER_CLASS` changes that:

```java
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class ExampleTest {
}
```

With `PER_CLASS`, one test class instance is used for the entire test class.

It also allows:

```java
@BeforeAll
void beforeAll() {
}
```

without requiring `static`.

# Database Testing with H2 + JDBC

The database examples use an **H2 in-memory database** so database operations can be tested without requiring a separately running MySQL server.

The basic flow is:

```text
JUnit
  ↓
Java test
  ↓
JDBC
  ↓
H2
  ↓
Database
```

## Connection

JDBC creates a `Connection` to the H2 database.

```java
DriverManager.getConnection(...);
```

## Creating a Table

Example:

```sql
CREATE TABLE products (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    price DOUBLE,
    stock INT
)
```

## `Statement`

Used for SQL where parameters are not required.

```java
Statement statement =
        connection.createStatement();

statement.executeUpdate(sql);
```

## `PreparedStatement`

Used when Java supplies values to SQL.

```java
String sql = """
        INSERT INTO products(name, price, stock)
        VALUES (?, ?, ?)
        """;

PreparedStatement statement =
        connection.prepareStatement(sql);
```

Then values can be supplied:

```java
statement.setString(1, "Laptop");
statement.setDouble(2, 60000);
statement.setInt(3, 5);
```

## `executeUpdate()`

Used for operations that modify data or database structure, such as:

```text
INSERT
UPDATE
DELETE
CREATE
DROP
```

Example:

```java
int rowsInserted = statement.executeUpdate();
```

## `executeQuery()`

Used for `SELECT` statements.

```java
ResultSet result = statement.executeQuery();
```

## `ResultSet`

Represents rows returned by a query.

```java
assertTrue(result.next());

assertEquals("Laptop", result.getString("name"));
assertEquals(60000, result.getDouble("price"));
assertEquals(5, result.getInt("stock"));
```

`result.next()` moves the cursor to the next available row.

# Resource Cleanup

The project demonstrates two important cleanup mechanisms.

## JUnit lifecycle cleanup

```java
@AfterAll
static void closeDatabase() {
    database.close();
}
```

This is used to close the shared database connection.

## Try-with-resources

```java
try (PreparedStatement statement =
         connection.prepareStatement(sql)) {

    statement.executeUpdate();
}
```

Java automatically closes the resource when the block finishes.

The same pattern can be used with:

- `Statement`
- `PreparedStatement`
- `ResultSet`

# Test Independence

A test should not normally depend on another test running first.

Avoid:

```text
testInsert()
    ↓
creates Laptop

testFind()
    ↓
assumes Laptop already exists
```

Prefer:

```text
testInsert()
    ↓
tests INSERT independently

testFind()
    ↓
prepares the data it needs
    ↓
tests SELECT independently
```

JUnit should be free to execute tests without your tests relying on a particular execution order.

# Standard Maven Structure

```text
project/
├── .mvn/
├── src/
│   ├── main/
│   │   └── java/
│   └── test/
│       └── java/
├── target/
├── pom.xml
└── mvnw / mvnw.cmd
```

- `src/main` → application code
- `src/test` → test code
- `target` → generated build output
- `pom.xml` → Maven project configuration
- `.mvn` → Maven Wrapper configuration
